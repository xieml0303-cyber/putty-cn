# 官方 PuTTY 0.85 与 putty-cn 0.85-cn2 源码对照

日期：2026-10-18
对照对象：官方 `putty-0.85.tar.gz`（Release 0.85，722 个文件） vs 本仓库 HEAD `d8497a4`（0.85-cn2）

## 一、结论

五个 exe 在官方原版里全部都有，不是汉化版新增的程序：

| 程序 | 官方 0.85 | 本仓库 dist |
|---|---|---|
| putty.exe | 有 | 有 |
| puttygen.exe | 有 | 有 |
| plink.exe | 有 | 有 |
| pscp.exe | 有 | 有 |
| psftp.exe | 有 | 有 |

官方 tarball 还能构建 `pageant.exe`、`puttytel.exe`（Windows）以及 `pterm`、`psocks`（Unix）。本仓库只交付上面五个，没有 pageant 和 puttytel。

汉化版相对官方，差异分三层：中文字符串翻译、本项目界面/串口改造、少量版本号与文档。协议、加密、终端核心代码未改。

## 四、功能对照

| 功能 | 官方 0.85 | 本汉化版 |
|---|---|---|
| 中文界面 | 无，全英文 | 有 |
| 串口页「厂商标准」下拉（华为/华三、思科、锐捷、中兴、Juniper、Aruba） | 无 | 有 |
| 串口自动匹配本机真实端口 | 无，用户手输 | 有，枚举注册表并回退首个物理串口 |
| 串口下拉只读、展开后点击任意位置收起 | 无，串口字段是普通输入框 | 有 |
| 配置页分组标题条灰底白字加粗 | 无，蚀刻边框 + 普通黑字 | 有 |
| 命令行工具中文提示 | 英文 | 中文 |
| 协议、加密、终端核心 | 原样 | 未改 |

官方源码证据：

- 官方 `config.c:3249`：串口页用 `ctrl_editbox(... "Serial line to connect to" ...)`，是普通文本输入框。
- 官方全树搜不到 `EnumPorts` / `QueryDosDevice` / `SetupDiGetClassDevs`，没有枚举本机串口的逻辑。
- 官方 `windows/controls.c:195` 有 `combobox()` 控件工厂，但只用于字体、字符集等页面，串口页未使用。
- 官方 `windows/dialog.c:154` 用 `SetWindowText(hwnd, pds->dp->wintitle)` 设置标准窗口标题；分组标题条走 `DrawEdge(EDGE_ETCHED)` 默认绘制。
- 官方 `config.c` 串口页只有 `serline`（选串口）和 `sercfg`（配参数）两组；汉化版多出 `serstd`（厂商标准）一组。

## 六、需要注意的点

1. 官方 `doc/` 下的 HTML、man、CHM 是构建产物，larryli 源码没有随附，不影响编译。
2. 官方 Windows 构建目标还有 `pageant` 和 `puttytel`，本项目 `dist/` 只发五个；需要的话可以从同一份源码补构建。
3. larryli 基线对 `psftp.c` 等文件删过文件头注释，diff 时会出现整段删除，属于注释清理，不是功能回退。
4. 本仓库的 `version.h` 为 0.85-cn2，官方为 Release 0.85；协议行为与官方 0.85 一致。

## 七、关于「汉化版缺东西」的澄清

结论：**源码没有任何缺失，缺的只是构建产物和打包范围。**

1. `pageant`、`puttytel`：`src/windows/CMakeLists.txt` 第 80、117 行仍有 `add_executable` 目标，`src/windows/pageant.c`（64 KB）也在。只是本项目交付范围定为五个 exe，没有编译这两个，也没有放进 `dist/`。补构建只需加两个 target。
2. `doc/` 下的 HTML、man、CHM：官方 `putty-0.85.tar.gz` 是发布包，里面带预生成的文档；larryli 的 git 源码仓库不提交生成物。仓库 `src/doc/` 有 35 个 `.but` 文档源文件，只缺构建时自动生成的 `version.but`。
3. `psftp`、`pscp` 的提示文字：larryli 基线只翻了一部分，本项目在 `ab8084b` 补完，属于翻译补齐，不是源码缺失。
4. 全量 diff 中「仅官方存在」的 16 项里，14 项是 `doc/` 生成物，另外 2 项是本仓库自己新增的 `.github/` 和 `readme.md`；没有任何 `.c` / `.h` 源文件只存在于官方一侧。
