# 终端内容贴屏幕左边修正（2026-10-22）

## 一、问题定位

现象：窗口看起来已贴左上角，但黑色终端区左侧仍有一条浅色竖条。

实测数据（改造前，窗口启动后立即用 `GetWindowRect` / `GetClientRect` / `ClientToScreen` 测量）：

| 指标 | 数值 |
|---|---|
| 窗口矩形 | L=0 T=0 R=552 B=914 |
| 客户区原点（屏幕坐标） | X=**7** Y=49 |
| 客户区尺寸 | 522×859 |
| 左边框 | 7 px |
| 右边框 | 23 px（17 滚动条 + 6 边框） |
| 上边框 | 49 px（23 标题栏 + 18 菜单 + 8 边框） |
| 下边框 | 6 px |
| SM_CXSIZEFRAME / SM_CXPADDEDBORDER | 4 / 4 |

结论：窗口外框确实在 (0,0)，但窗口左侧 7 px 属于非客户区（4 px 可调边框 + 4 px 内边距，DWM 取整为 7），终端客户区只能从 x=7 开始，因此屏幕边缘留下一条 7 px 的边框条。这不是位置没设对，而是**边框本身占位**。

## 二、修改方式

`src/windows/window.c` 的启动校正块中，在最终 `SetWindowPos` 之前用 `ClientToScreen` 求出客户区原点相对窗口矩形的偏移，即左边框宽度，再把窗口放到 `-left_border`：

```c
client_origin.x = 0;
client_origin.y = 0;
ClientToScreen(wgs->term_hwnd, &client_origin);
left_border = client_origin.x - wr.left;

SetWindowPos(wgs->term_hwnd, NULL, -left_border, 0, ...);
```

只移动水平位置，垂直方向仍为 0，标题栏完整留在屏幕内，可正常拖动、最小化、关闭。左边框宽度是量出来的而非硬编码，不同 DPI/边框样式的机器上自适应。

## 三、验证

改造后同一脚本测量：

| 指标 | 改造前 | 改造后 |
|---|---|---|
| 窗口矩形 L | 0 | **-7** |
| 客户区原点 X | 7 | **0** |
| 客户区尺寸 | 522×859 | 522×859（不变） |
| 窗口右边界 | 552 | 545（仍在屏幕内） |

截屏确认（`reports/edge-check.png`，仅截左上 620×380）：黑色终端区左侧紧贴屏幕边缘，浅色竖条消失。

## 四、已知副作用

1. **标题栏图标左端被裁约 7 px**。窗口整体左移后，标题栏最左侧的窗口图标有一小部分移出屏幕，视觉上仍可辨认，不影响标题栏拖动区域。
2. **窗口左边界坐标为负数**。单显示器下无影响；多显示器且主屏左侧还有屏幕时，这 7 px 会落在左侧显示器上。若日后需要多屏适配，可加 `MonitorFromWindow` 判断。
