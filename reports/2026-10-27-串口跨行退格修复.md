# 串口跨行退格修复报告

日期：2026-10-27
仓库：`C:\Users\Wrok\Repos\putty-cn`
涉及文件：`src/terminal/terminal.c`、`src/test/test_terminal.c`

## 一、问题现象

用户报障（原话）：

> 如果输入的代码过长掉到了第二行，在第二行退格后无法退格到第一行。这个 bug 似乎是串口独享的，远程登录未见异常。

## 二、根因

`terminal.c` 里 BS 和 DEL 是两个独立分支，语义不一致：

| 控制符 | 来源 | 改动前行为 |
| --- | --- | --- |
| `0x08` BS | 远程 Linux pty、`\b \b` 序列 | 列 0 时跨到上一行末列，正常 |
| `0x7F` DEL | 串口设备回显、`bksp_is_delete=true` | `if (curs.x && !wrapnext) curs.x--;` —— **只在同行左移，列 0 直接不动** |

改动前 DEL 分支原始代码：

```c
if (c == '\177' && term->termstate < DO_CTRLS && has_compat(OTHER)) {
    if (term->curs.x && !term->wrapnext)
        term->curs.x--;
    term->wrapnext = false;
    if (!term->no_dbackspace) {
        check_boundary(term, term->curs.x, term->curs.y);
        check_boundary(term, term->curs.x + 1, term->curs.y);
        copy_termchar(scrlineptr(term->curs.y), term->curs.x, &erase_char);
    }
    seen_disp_event(term);
}
```

于是：光标走到续行第 0 列后，`curs.x == 0`，判断条件为假，光标卡住，破坏性退格反复擦同一格 —— 表现为「第二行退不上去」。

### 为什么串口独享

- 远程登录（ssh 到 Linux）时，pty 的 line discipline 回显退格用 `\b \b`（BS + 空格 + BS），走 BS 分支，本来就跨行 → 无异常。
- 串口 console 由设备自己做行编辑，不少设备（含华为 VRP 系列）把退格回显成 `0x7F`(DEL)，走 DEL 分支 → 命中上面的卡死逻辑。
- 另有一条独立路径：`src/windows/window.c` 的 Shift+Backspace 在串口下强制发 `0x7F`（`window.c:4673-4677`），同样走 DEL 分支。

## 三、修复方案

抽公共函数 `term_cursor_backspace(Terminal *term, bool require_wrapped)`（`terminal.c:3230` 附近），BS 与 DEL 共用，用 `require_wrapped` 区分跨行条件：

- `require_wrapped == false`（BS）：保持上游语义，无条件跨到上一行末列。
- `require_wrapped == true`（DEL）：只有当上一行带 `LATTR_WRAPPED`（软换行续行）时才跨行。

DEL 不跨硬换行的理由：`\r\n` 之后上一行是已完成的历史输出，破坏性退格再去擦它的末字符会篡改已有内容。

`LATTR_WRAPPED2` 的处理（双宽字符折行时右列留空的补偿）原样保留在公共函数里，两条路径共享。

BS 分支的对外行为未变，只是代码从内联搬进了函数。

## 四、验证

### 4.1 单元测试（`src/test/test_terminal.c`）

新增 `test_del_backspace()`，24×80 终端，`wrap=true`：

| 用例 | 断言 |
| --- | --- |
| 打印 161 个 `a` 后连续 DEL | 第一次 DEL 停在 y=2,x=0；第二次 DEL 跨到 y=1,x=79，cell(79,1) 变空格、cell(78,1) 仍是 `a` |
| `prompt>` + `\r\n` 后 DEL | 光标不动，prompt 不被破坏（硬换行不跨） |
| `abc\r\n` 后 BS | 跨到 y=0,x=79（BS 无条件跨行，行为未变） |

结果：`ninja test_terminal` 通过，`./test_terminal.exe` 输出 `Test suite passed`，exit=0。

### 4.3 COM3 真机实测

环境：FTDI `USB Serial Port (COM3)` → 华为 AR6280 路由器 console，9600 8N1，提示符 `<LZGA_JR_HW_AR6280_JingLanSuo>`，已登录。

| 步骤 | 观察 |
| --- | --- |
| 输入 53 个 `a` + 提示符 30 字符 | 第一行填满，续行 18 个 `a`，光标停在续行末 |
| 退格 18 次 | **光标回到第一行**（`>aa` 之后），跨行成功 |
| Ctrl+U 清行 | 设备重画，画面出现错位残留 |

真机的限制：AR6280 的行编辑收到退格后是「删字符 + 重画整行」，屏幕内容由设备重绘，PuTTY 的终端光标动作被设备输出掩盖，因此真机上无法逐字节区分新旧版本的差异。上面的 4.2 才是能精确判定 DEL 分支行为的实验。

另注：真机实测中发出的是 `0x08`（串口普通 Backspace 被 `window.c:4666` 强制成 BS），设备回显走重画；用户遇到 `0x7F` 的路径可能是 Shift+Backspace 或其它型号设备。
