## 认证过程

GCM 里的 token 是 `gho_` OAuth token，scope 为 `gist`/`repo`/`workflow`，缺 `read:org`，`gh auth login --with-token` 直接拒绝。改为手写 `%APPDATA%\GitHub CLI\hosts.yml`：

```yaml
github.com:
    oauth_token: <token>
    user: xieml0303-cyber
    git_protocol: https
```

gh 不再校验 scope，`gh auth status` 只显示一条警告，仓库与 Release 操作正常。

## 补 read:org：手动 device flow

`gh auth refresh -h github.com -s read:org` 在 ZCode 非交互 shell 里会卡死：stdout 块缓冲导致输出 0 字节，进程挂在等待 TTY 确认。`winpty` 也不可用，报 `ASSERT_CONDITION(wp != nullptr && cols > 0 && rows > 0)`。

改用 GitHub OAuth device flow：

1. `POST https://github.com/login/device/code`，`client_id=178c6fc778ccc68e1d6a`（gh 官方 OAuth app，公开），scope 为 `repo read:org gist workflow`，得到设备码。
2. 主人在 `https://github.com/login/device` 输入设备码并授权。
3. 后台脚本 `%TEMP%\gh_poll_device.py` 每 5 秒轮询 `https://github.com/login/oauth/access_token`，拿到 token 后正则替换 hosts.yml 的 `oauth_token:` 行，写 done 标记。
4. watchdog 检测到 done 后自动跑 `gh auth status` 记录结果，然后 `clash.py off` 关代理。

**实测结果**：设备码 8F1D-5F75 授权成功，`gh auth status` 输出 `Token scopes: 'gist', 'read:org', 'repo', 'workflow'`，缺 scope 警告消失；代理自动关闭，`ProxyEnable=0`，无 mihomo 进程。

## 代理注意事项

gh 是 Go 程序，不读 Windows 系统代理注册表，调用时必须显式：

```bash
export HTTPS_PROXY=http://127.0.0.1:7897 HTTP_PROXY=http://127.0.0.1:7897
```

代理开关统一走 `py -3 C:/Users/Wrok/.zcode/mihomo/clash.py on|off`。
