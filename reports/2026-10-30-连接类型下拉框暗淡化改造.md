# 连接类型下拉框暗淡化改造报告

日期：2026-10-30
版本：0.85-cn2
涉及文件：`src/config.c`、`src/windows/controls.c`、`src/windows/platform.h`、`src/dialog.h`、`src/dialog.c`、`src/unix/dialog.c`、`src/test/fuzzterm.c`

## 一、背景与目标

配置窗口「会话」页的连接类型区域由一组单选按钮（SSH、串口、其他：）与「其他：」右侧的协议下拉框构成。此前单选按钮已完成改造：当前选中项以正常文字色绘制，未选中项以灰色绘制，视觉上能一眼看出当前生效项。

但下拉框仍保持原生组合框外观：白底、立体边框、黑色文字。当「其他：」未被选中时，这个白底下拉框在视觉上比旁边暗淡的「其他：」标签更醒目，造成主次颠倒——用户在 SSH 模式下，视线会先被那个用不上的下拉框吸引。

本轮目标：让下拉框在「其他：」未被选中时也呈暗淡状态，与单选按钮的暗淡规则保持一致；「其他：」被选中时恢复为正常外观。同时要求保留下拉框的原生外观与全部交互能力。

## 二、方案演进与失败路径

### 2.1 首版方案（已撤回）：纯文字呈现

首版把下拉框的显示面完全覆盖，只绘制当前选中项的文字，隐藏边框、白底与下拉箭头，使控件看起来像一段纯文本，点击后仍弹出列表。

实测问题：

- 视觉上失去了控件的可发现性。下拉箭头消失后，用户无法从外观判断这里可以点击。
- 与旁边的「其他：」标签视觉重量过于接近，两者层级关系变得模糊。
- 控件在界面上的存在感与「下拉框」这一功能不匹配。

结论：方案方向偏离需求。用户要求的是"变暗淡"，不是"变成文字"。该实现已完整撤回，撤回范围包括 `dialog.h` 中的 `plaintext` 标志、`dialog.c` 的初始化、`windows/controls.c` 的 `staticddlplain` 与 `plainddl_*` 子类化绘制、`unix/dialog.c` 的空实现、`test/fuzzterm.c` 的桩函数，以及 `config.c` 中的启用点。撤回后经 `git diff` 核对，`dialog.c`、`dialog.h`、`unix/dialog.c`、`test/fuzzterm.c`、`windows/platform.h` 五个文件的差异归零。

### 2.2 尝试二：WM_CTLCOLOR 消息（失败）

经典控件模式下，控件的背景与文字颜色通过 `WM_CTLCOLOR*` 消息向父窗口询问，父窗口返回画刷并设置文字色。这是改变控件配色的标准途径。

实现方式：在 `windows/dialog.c` 的 `pds_default_dlgproc` 中增加 `WM_CTLCOLORSTATIC`、`WM_CTLCOLOREDIT`、`WM_CTLCOLORLISTBOX` 三个分支，转交新增的 `winctrl_handle_colour` 处理；该函数按控件 ID 查找对应的 `winctrl`，若该控件被标记为暗淡且是下拉框，则 `SetTextColor` 设为灰色、`SetBkColor` 与返回值均设为对话框背景画刷。

实测结果：颜色完全未变。

诊断过程：加入临时文件日志，记录消息到达与控件匹配情况。日志显示：

- `setdim` 被正确调用，`dim=1`；
- `WM_CTLCOLORSTATIC`（0x0138）确实到达父窗口，共 32 次；
- 其中包含协议下拉框（控件 ID 1053）发出的请求；
- 匹配结果 `id=1053 found=1 type=5 dim=1 height=0`，即处理函数确实走到了返回灰刷子的分支。

但像素统计显示背景仍为 (225,225,225)，文字仍为纯黑 (0,0,0)。

根因：该组合框为 `CBS_DROPDOWNLIST` 风格，且**没有内部子窗口**（`EnumChildWindows` 结果为空），其显示面完全由组合框自身绘制。它虽然会发出 `WM_CTLCOLORSTATIC`，但只用于询问文字背景色，并不采纳返回的画刷来重绘整个面；`SetTextColor` 亦被忽略。这是该控件实现层面的行为，无法通过消息约定改变。

结论：`WM_CTLCOLOR` 路线不可行，相关代码已全部移除。

### 2.3 最终方案：借用原生禁用态外观

观察到该组合框存在一个天然可用的"暗淡"外观——**禁用态**。实测禁用后的配色：

| 部位 | 启用态 | 禁用态 |
| --- | --- | --- |
| 客户区背景 | (225,225,225) | (204,204,204) |
| 边框 | (173,173,173) | (191,191,191) |
| 文字/箭头 | (0,0,0) 等深色 | (109,109,109) 等浅灰 |

这正是 Windows 原生的"不可用"观感，且边框、下拉箭头、文字排版全部保留，与需求高度吻合。

难点在于：真禁用会同时禁用交互（无法点击、无法用键盘操作），而需求只要求外观变化。

实现思路：**在需要暗淡时，把控件临时禁用一瞬，抓取其客户区画面存入位图，随即恢复启用，之后每次重绘时把这张位图贴在控件表面。**

关键验证（先行验证，后写代码）：

1. 临时 `EnableWindow(FALSE)` 后 `BitBlt` 抓图，可得到完整禁用态画面；
2. 恢复 `EnableWindow(TRUE)` 后，`CB_SHOWDROPDOWN` 仍能正常展开列表——交互未受破坏；
3. `WM_PRINTCLIENT` 对该控件返回全黑（不支持），故改用屏幕 `BitBlt`。

## 三、实现细节

### 3.1 接口层

`src/dialog.h` 中为 `listbox` 结构增加 `bool dimmed` 字段，并声明：

```c
void dlg_listbox_setdim(dlgcontrol *ctrl, dlgparam *dp, bool dim);
```

`src/dialog.c` 在 `ctrl_droplist` 与 `ctrl_draglist` 中初始化 `dimmed = false`。

`src/unix/dialog.c` 与 `src/test/fuzzterm.c` 提供空实现，保证跨平台与测试桩可编译。GTK 前端无对应能力，注释中已说明。

### 3.2 Windows 端核心（`src/windows/controls.c`）

新增结构体保存每个受控下拉框的状态：

```c
struct combo_dim {
    HWND combo;
    HBITMAP shot;       /* 缓存的禁用态画面 */
    int shotw, shoth;   /* 画面尺寸，用于尺寸变化时作废 */
    int shotsel;        /* 画面所对应的选中项索引 */
    bool dim;
    bool grabbing;      /* 抓图期间置位，避免递归 */
};
```

子类过程 `combo_dim_subclass` 拦截 `WM_PAINT`：

- 若处于暗淡态且不在抓图过程中，先检查缓存是否仍然有效：尺寸与当前客户区不一致、或选中项索引与当前不一致时，作废缓存。
- 无有效缓存时：先 `EndPaint` 结束本次绘制，调用 `DefSubclassProc` 完成一次正常绘制，然后 `EnableWindow(FALSE)` → 抓图 → `EnableWindow(TRUE)`，再请求一次重绘。
- 有有效缓存时：先正常绘制，随后用 `GetDC` 取屏幕 DC，把缓存位图 `BitBlt` 覆盖上去。

同时在 `WM_COMMAND` 中监听 `CBN_SELCHANGE`，以及 `WM_NCDESTROY` 中释放位图与子类化。

`dlg_listbox_setdim` 负责首次调用时安装子类化、更新 `dim` 标志、在恢复亮态时释放缓存，并请求重绘。

`dlg_listbox_select` 在改变下拉框选中项后作废缓存，避免画面中的文字停留在旧选项。

### 3.3 状态判定（`src/config.c`）

新增 `config_protocols_setdim`：判断当前协议是否属于单选按钮组。**此处刻意不硬编码协议值，而是遍历 `protradio->radio.buttondata[]` 比对**，因为哪些协议获得单选按钮取决于编译进来的后端。

这一决策来自一次实测纠错：初版硬编码为 `proto != PROT_SSH && proto != PROT_SERIAL && proto != PROT_RAW`，把 `PROT_RAW` 当作"非单选协议"。但实际协议列表中 Raw 与「裸 ssh 连接」都位于下拉框内、属于「其他：」管辖，导致选中 Raw 时下拉框仍保持暗淡。改为遍历按钮组后，判定与实际 UI 结构一致。

调用点有两处：

1. `EVENT_REFRESH` 分支末尾，当刷新的是 `protradio` 或 `protlist` 时同步；
2. `EVENT_VALCHANGE` 分支末尾，当控件是 `protradio` 或 `protlist` 时同步。后者覆盖了"在下拉列表中直接选择某项"的路径——该操作会通过 `EVENT_SELCHANGE` 自动选中「其他：」，此时下拉框应立即转为亮态。

## 五、边界与已知限制

1. **抓图瞬间的闪烁风险**：抓图时控件被禁用一瞬（约毫秒级）。实测未观察到可见闪烁，因该过程发生在 `WM_PAINT` 返回之后、且随即请求重绘。若将来在高负载或远程桌面场景下出现闪烁，可改为在 `dlg_listbox_setdim` 首次调用时一次性抓图。
2. **高 DPI 下的尺寸变化**：缓存以客户区尺寸为有效性判据，DPI 变化导致控件尺寸改变时会自动作废并重新抓图。
3. **主题化（comctl32 v6）未启用**：本程序以 `/manifest:no` 编译，运行于经典控件模式。若将来启用 v6 主题，禁用态配色会由主题决定，方案本身仍然成立（抓的仍是原生禁用态），但配色观感会随主题变化。
4. **GTK 前端无此效果**：`unix/dialog.c` 中为空实现，下拉框保持 GTK 原生外观。该改造仅面向 Windows 前端。
