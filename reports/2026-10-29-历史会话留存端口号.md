# 历史会话留存端口号 —— 改造与验证报告

日期：2026-10-29
版本：0.85-cn2
产物：`dist/putty.exe`，1,857,887 字节，SHA256 `fd3f345dc911c91d338def631e8bc74a36bcabd2b4a11643e2eafced4d5f2354`

## 一、改造前的问题

「历史会话」列表原先只留存主机名，端口号完全没有被持久化。

存储实现位于 `src/windows/storage.c` 的 `RecentHosts` 注册表键下，每个条目是一个
REG_SZ 值，键名为顺序索引 `"0"`、`"1"`……，值为纯主机名字符串。读取函数
`get_recent_hosts()` 返回 `char **`，写入函数 `add_recent_host(const char *host)`
只接收主机名一个参数。整个链路里不存在端口号的位置。

界面侧在 `src/config.c`：

- `struct sessionsaver_data` 只持有 `hostbox`（主机名框），没有端口框的引用。
- `select_history_entry()` 单击列表项时只调用 `dlg_editbox_set(hostbox, ...)` 并
  同步 `CONF_host`。
- `sessionsaver_handler()` 的「打开」分支调用
  `add_recent_host(conf_get_str(conf, CONF_host))`，端口 `CONF_port` 从未被记录。

因此单击历史条目后，上方「端口」框始终保持当前值不变，即用户所报告的现象。

## 二、改造内容

### 2.1 存储层接口（`src/storage.h`）

用带端口的结构体替换裸字符串数组：

```c
struct recent_conn {
    char *host;
    int port;      /* 0 表示该条目产生于端口留存功能之前 */
};

struct recent_conn *get_recent_conns(int *count);
void add_recent_conn(const char *host, int port);
void del_recent_conn(const char *host, int port);
void free_recent_conns(struct recent_conn *list, int count);
```

### 2.2 Windows 存储实现（`src/windows/storage.c`）

注册表键仍为 `HKCU\Software\SimonTatham\PuTTY\RecentHosts`，在原有索引值之外
为每条记录增加一个伴随值：

| 值名 | 类型 | 内容 |
| --- | --- | --- |
| `0`、`1`、…… | REG_SZ | 主机名 |
| `0.port`、`1.port`、…… | REG_DWORD | 端口号 |

设计要点：

- **向后兼容**：旧格式条目没有 `.port` 伴随值，读取时端口回落为 0。调用方遇
  到 0 时不动端口框，保持协议默认值。用户已有的 15 条历史无需迁移即可继续使用。
- **同一主机不同端口视为两条独立记录**：`add_recent_conn()` 的去重条件为
  `host 相同 && port 相同`。`host:22` 与 `host:2222` 是两个不可互换的连接目标，
  合并会丢信息。删除逻辑同理，只删匹配的那一条。
- 端口为 0 时不写 `.port` 值，避免注册表里堆无意义的值。

### 2.3 Unix 侧空实现（`src/unix/storage.c`）

同步更新函数签名与 `struct recent_conn` 释放逻辑，保证跨平台可编译。Unix 侧
历史功能本就未实现（返回空列表），行为不变。

### 2.4 界面层（`src/config.c`）

- `struct sessionsaver_data` 增加 `portbox` 字段，在
  `setup_config_box()` 创建端口控件时赋值 `ssd->portbox = c`。
- 新增 `recent_entry_text()`：列表项显示为 `host:port`，无端口时只显示
  `host`。这样同一主机的不同端口在列表中可直接区分。
- `select_history_entry()`：单击或双击条目时，同时回填主机名框与端口框，并
  同步 `CONF_host`、`CONF_port`。
- 「打开」分支改为
  `add_recent_conn(conf_get_str(conf, CONF_host), conf_get_int(conf, CONF_port))`。
- 删除按钮改为 `del_recent_conn(host, port)`，精确删除选中条目。

### 2.5 顺带修复的串口串扰缺陷

改造过程中发现一个改造前即存在的缺陷：串口后端下，主机名框复用为串口选择器
（绑定 `CONF_serline`），相邻的端口框复用为波特率框（绑定 `CONF_serspeed`）。
原代码无条件地把网络历史条目回填进主机名框，并在点「打开」时用 `CONF_host`
记录历史，导致：

1. 串口模式下单击网络历史条目，会把网络主机名写进只读的串口选择框。
2. 串口连接会把上一次残留的 `CONF_host` 当成一条网络记录写进历史。

修复方式：`select_history_entry()` 在 `PROT_SERIAL` 下直接返回；「打开」分支
在 `PROT_SERIAL` 下不写历史。历史列表的语义明确为「网络连接历史」，串口连接
不进入该列表。

## 六、已知限制

- 端口留存依赖「打开」时读取当前 `CONF_port`。若用户在协议切换时选择了非默认
  端口后又切回，实际记录的是切换后框内显示的值，与最终发起连接所用值一致。
- 历史条目上限仍为 20 条（`MAX_RECENT_HOSTS`），与改造前一致。
- 同一主机不同端口占用两条记录，会更快触及上限。这是为保证语义正确所做的
  取舍。
