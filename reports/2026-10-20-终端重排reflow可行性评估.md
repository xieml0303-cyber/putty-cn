# PuTTY 中文版：窗口尺寸变化触发的终端重排（Reflow）可行性评估

- 日期：2026-10-20
- 评估对象：`src/terminal/terminal.c`（8209 行）、`src/terminal/terminal.h`、`src/windows/window.c`
- 结论：**技术上可行，且现有架构已有一半地基；但不是小改动，建议分两期实施**

---

## 一、代码现状事实

### 1.1 已有的地基（比预期好）

| 机制 | 位置 | 说明 |
|---|---|---|
| 软换行标记 | `LATTR_WRAPPED` / `LATTR_WRAPPED2`，设置点见 `terminal.c:3328`、`3394`、`3473` | 自动换行发生时给**上一物理行**打标记，已能区分"逻辑续行"与"真换行" |
| 行宽与终端宽解耦 | `struct termline { int cols; ... }`（`terminal.h:52`） | 每行自带宽度，天然支持"行比终端宽"的状态 |
| 惰性重分配 | `lineptr()`（`terminal.c:1225` 附近）、`resizeline()`（`terminal.c:1066`） | 缩窄**不立即截断**，只在放大时扩容；注释明确说明目的是"连续 resize 不无偿丢数据" |
| 跨行拼接已有实现 | `sel_spread_half()` `terminal.c:6976-7075`、粘贴逻辑 `6680` 附近 | 选择/复制已按 `LATTR_WRAPPED` 跨物理行拼接，可直接复用其拼行规则 |
| 拖动中不重排 | `src/windows/window.c:2199` `wm_size_resize_term` | 交互式拖动（`wgs->resizing`）期间只置 `need_backend_resize`，**松手才调 `term_size`**——性能压力天然可控 |
| 备用屏天然豁免 | `term_size()` `terminal.c:2207`，alt screen 在 resize 时整体 `newtree234` 重建 | vim/htop/tmux 等全屏 TUI 内容本来就每次 resize 由程序自己重绘，无需参与重排 |

### 1.2 缺的另一半

1. **没有重排函数**：`resizeline()` 只做"截断/补空格"，不会把被截断的内容搬到下一行，也不会把续行合并回上一行。
2. **截断是永久的**：一旦缩窄后有输出落到某行，`check_line_size()`（`terminal.c:1278`）会把该行 `resizeline` 到新宽度，超宽内容物理丢弃，拉宽也回不来。这是用户当前看到的"长行被折断/丢失"的直接原因。
3. **滚动缓冲是压缩存储**：`compressed_scrollback_line`（`terminal.c:693`），行宽 `cols` 被写进压缩流。重排会改变行数与内容，必须解压→重排→重压缩。
4. **行数与位置会变**：变窄时一行拆成多行（行数增加，需要把内容挤进 scrollback）；变宽时多行合并（行数减少，屏幕底部要补空行）。`curs`、`savecurs`、`alt_*`、`disptop`、`tempsblines`、`marg_t/marg_b` 全部要重映射。

## 二、方案对比

### 方案 A：仅屏幕区重排（推荐作为第一期）

只对 `term->screen`（当前可见的 rows 行）+ 当前滚动视图内的行做逻辑行拼接与重新切分，不动 scrollback。

- 改动量：核心函数约 250～350 行 C，`term_size` 集成约 80～120 行
- 覆盖场景：正在输入的长命令行、刚输出完还在屏幕上的长行
- 风险：中低。行数变化只在与 scrollback 的交界处发生，逻辑简单
- 缺点：向上翻历史时，旧内容仍是按旧宽度截断的，视觉上"上半截不重排"

### 方案 B：全量重排（屏幕 + 全部 scrollback）

- 改动量：方案 A + 约 250～400 行（解压/重压、逻辑行跨 scrollback 边界、行索引重建）
- 覆盖场景：完整一致的历史重排
- 风险：中高。`savelines` 可配置到很大（`CONF_savelines` 无硬上限，GUI 输入框允许任意整数），整表解压+重建的峰值内存与耗时不可控，需要加阈值降级
- 额外问题：逻辑行可能跨越 scrollback 与 screen 边界，需要跨树拼接

### 方案 C：绘制层软折行（不推荐）

不改变数据结构，只在 `do_paint` 时把超宽行折成多行画出来。

- 看似改动小，实际要新建一套"视觉行 ↔ 逻辑行"坐标系，光标定位、选区、滚动条、鼠标点击全部要换算
- 与现有 `disptext`（按 `term->cols` 逐格绘制、`term_paint` 已按行列裁剪）冲突面大
- 结论：比方案 A 更麻烦，且无法解决"缩窄后有输出就丢数据"

## 三、推荐路线

**第一期做方案 A，第二期再扩到方案 B。** 理由：

1. 用户最痛的是"正在敲的命令 / 刚输出的长行被折断"，屏幕区就能解决 80% 的体感问题。
2. 第一期把"逻辑行拼接 + 按新宽度切分 + 光标锚定"的算法打磨正确，第二期只是把数据源从 `screen` 扩到 `scrollback`，风险可控。
3. Windows 前端拖动中不调 `term_size`，第一期甚至不需要做防抖。

### 3.1 第一期改动点清单

| 文件 | 函数 | 改动 |
|---|---|---|
| `src/terminal/terminal.c` | 新增 `reflow_screen()` | 从光标所在逻辑行开始，向上向下按 `LATTR_WRAPPED` 聚合逻辑行；按 `term_char_width()` 重新切分为新宽度的物理行；写回 `term->screen` |
| 同上 | `term_size()` | 在 rows 调整**之后**、`cols` 生效时调用 `reflow_screen()`；处理行数增减与 scrollback 的换入换出；重映射 `curs.y`、`savecurs`、`disptop` |
| 同上 | `lineptr()` / `check_line_size()` | 增加"reflow 进行中"标志，避免惰性 resize 与批量重排互相打架 |
| `src/windows/window.c` | 无需改动 | 已有松手才 resize 的行为 |

### 3.2 切分算法要点

1. 逻辑行 = 一串 `LATTR_WRAPPED` 相连的物理行（最后一行为非 wrapped）。
2. 拼接时若前一物理行带 `LATTR_WRAPPED2`，丢弃其最后一格的填充空格（双宽字符停在最后一列的既有处理，见 `terminal.c:3394`）。
3. 按新宽度切分时以**字符宽度**为单位，`UCSWIDE`（双宽字符的占位格）不能被拆到两行；切分点落不下时整体下移。
4. 行尾刚好填满但后续没有字符的情况**不设** `LATTR_WRAPPED`（`terminal.c:3469` 的 `wrapnext` 机制决定），重排时保守地视为独立行，不合并——宁可少合并一次，不能错误合并。
5. `LATTR_TOP` / `LATTR_BOTTOM` / `LATTR_MODE`（双高、双宽模式行）不参与重排，原样保留。xterm 也不重排这类行。
6. 备用屏（`alt_which`）不参与重排，沿用现有的"重建清空、由 TUI 自己重绘"行为。

## 四、风险清单

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| 1 | 惰性 `line->cols` 契约被打破 | 重排后若仍有行 `cols != term->cols`，`lineptr` 会再次触发扩容/截断，可能撕裂内容 | 重排结束强制全部行 `cols == term->cols`；加重排中标志位 |
| 2 | 宽字符跨行拆分 | 中文/emoji 被劈成半个字，或出现 `UCSWIDE` 孤立占位 | 以 `term_char_width()` 为单位切分，边界回退一格 |
| 3 | 行数增减导致位置漂移 | 光标跑到错误行、滚动位置跳变、选区错位 | 以光标为锚点重算；`term_size` 开始时已 `deselect()`，选区问题天然规避 |
| 4 | scrollback 压缩与行数变化（第二期） | 解压全表内存峰值；`tempsblines` 与 `sblen` 关系错乱 | 加 `savelines` 阈值（如 >50000 行则跳过重排）；分批处理 |
| 5 | 性能 | 大 `savelines` 时松手卡顿 | 第一期只重排 rows 行（24～60 行，微秒级）；第二期限额 |
| 6 | 无单元测试 | 回归全靠手测 | 建议先补 `tests/` 下的行缓冲测试或至少一套脚本化场景 |
| 7 | 宽字符 + 选择/复制语义 | 重排后复制内容与视觉不一致 | 复用 `line_cols()` / `LATTR_WRAPPED2` 的既有逻辑 |

## 五、验收方法

1. 长行折行：`seq 1 300 | awk '{printf "%s ", $1}'; echo` 造一条超长行，缩窄窗口应折成多行显示、内容不丢；拉宽应合并回一行。
2. 输入中命令：在提示符敲超过屏宽的命令，缩窄/拉宽时光标位置与文本保持连续。
3. 中文宽字符：`printf '中%.0s' {1..200}; echo`，折行处不得出现半字。
4. 全屏 TUI：vim / htop 中拖动窗口，不得崩溃、不得出现残影（alt screen 走原路径）。
5. 禁用自动换行：`printf '\e[?7l'` 后输出超长行，不得重排（`wrap` 为 false 时逻辑行不成立）。
6. 滚动回看：输出 500 行后向上翻，第一期允许旧内容沿用旧宽度（已知限制），但滚动条与行数不得错乱。
7. 性能：默认 `savelines=2000` 下，拖动松手到画面稳定的延迟应 < 50ms。

## 七、最终判断

**能做。** 现有代码已经留了软换行标记、行宽解耦、惰性重分配和跨行拼接四块地基，主要工作是补一个"逻辑行拼接 → 按新宽度切分 → 回写"的重排器，以及 `term_size` 里的位置重映射。

不建议一次性做全量 scrollback 重排：`savelines` 无上限，全表解压重建的代价不可控，且第一期屏幕区方案已经能解决绝大多数体感问题。

不建议走"绘制层软折行"的捷径：坐标系一改，光标、选区、鼠标、滚动条全要跟着换算，代价高于直接改数据结构。
