## 三、界面层逻辑（config.c）

1. **构建（config.c:2298-2321）**：五个单选在「会话/日志记录」控件组里。SSH 相关按钮（"SSH 包" / "SSH 包和 RAW 数据"）与底部「指定 SSH 包日志记录设置」分组**只有当协议是 SSH 时才创建**——`midsession && protocol == PROT_SSH`（会话中重开配置）或 `!midsession && backend_vt_from_proto(PROT_SSH)`（新建连接且当前协议候选里有 SSH）。所以 Telnet/串口会话里根本看不到这两个按钮。
2. **loggingbuttons_handler（config.c:583-608）**：这个单选组不走通用处理器。刷新（EVENT_REFRESH）时若当前配置的 logtype 在这组按钮里找不到（例如配置保存的是 SSH 包日志，但现在面板没有 SSH 按钮），自动回退到第 0 项「无(T)」并把 CONF_logtype 强制改回 LGTYP_NONE，防止残留一个"看不见但生效"的日志模式。
3. 汉化版的界面文本直接写死在 config.c 源码里（本项目汉化方式为改源码文本）。

## 四、日志引擎（logging.c）

### 4.1 状态机

LogContext 有四个状态（logging.c:17）：`L_CLOSED`（未开）→ `L_OPENING`（异步等用户回答询问弹窗）→ `L_OPEN`（正常写）→ `L_ERROR`（写失败/被取消，永久静默丢弃后续写入）。

### 4.2 写入主流程

- **logwrite（logging.c:35-56）**：一切写入的总入口。状态是 CLOSED 就先调 logfopen 开文件；OPENING 就把数据塞进 bufchain 队列暂存；OPEN 就 fwrite；ERROR 直接丢。fwrite 失败会关文件并置 ERROR，向事件日志报 "Disabled writing session log..."——之后永远不再尝试，避免磁盘满时反复弹错。
- **logprintf**：logwrite 的 printf 包装。
- **logflush（logging.c:78-83）**：对 OPEN 状态的文件 fflush。「快速刷新缓存到日志文件」勾上时，后端每收到一批数据都会调它（由各 backend 的 logflush 调用点触发），让日志实时落盘，便于用别的编辑器 tail 看日志；代价是更多磁盘 IO。

### 4.3 打开文件与三种冲突处理（logging.c:158-194 + 90-151）

1. logfopen 前置检查：state 必须是 CLOSED（防重复打开）、logtype 非 0（选了「无」就什么都不做）。
2. 调 xlatlognam 把模板文件名里的占位符替换掉（见 4.5）。
3. `open_for_write_would_lose_data()` 探测目标文件是否已存在且有内容：
   - 不存在/空文件 → 直接以 "wb" 新建（mode=2）。
   - 已存在 → 按 CONF_logxfovr：OVR→mode 2（wb 覆盖），APN→mode 1（ab 追加），ASK→调 `lp_askappend` 弹窗异步等用户回答（此刻状态=L_OPENING，期间日志数据进队列暂存）。
4. logfopen_callback：真 fopen。失败（磁盘错误/权限）→ L_ERROR 并用 lp_logging_error 醒目报错。
5. 成功且 CONF_logheader 开着 → 写一行头 `=~=~=~=~=~=~=~=~=~=~=~= PuTTY log 2026.10.30 12:34:56 =~=~=~=~=~=~=~=~=~=~=~=`（logging.c:111-117）。这就是「包含行首标题」的产物。
6. 向事件日志写一条 "Appending/Writing new session log (xxx mode) to file: ..."。
7. 把 OPENING 期间积压的队列数据一次性写入并 flush。

### 4.4 GUI 询问弹窗（windows/dialog.c:1363-1395）

win_gui_askappend：是/否/取消三键 MessageBox，**默认焦点在「否」（追加）**（MB_DEFBUTTON3），返回值 2=覆盖、1=追加、0=取消并禁用本会话日志。命令行版对应实现在 windows/console.c:553。

### 4.5 文件名占位符（xlatlognam，logging.c:435-504）

逐字符扫描文件名，`&` 开头触发替换：`&Y`=年、`&M`=月、`&D`=日、`&T`=时分秒(HHMMSS)、`&H`=主机名（conf_dest，串口时是串口名）、`&P`=端口（界面说明文本没提但代码支持）、`&&`=字面 &、`&+其他字符`=原样输出该字符。所有由占位符展开出来的字符都过一遍 filename_char_sanitise，把 Windows 文件名非法字符（如 IPv6 主机名里的冒号、斜杠）替换成合法字符，防止展开后路径越界。

### 4.6 数据从哪来（两个来源）

1. **终端层（terminal.c）**：处理终端输出时按字节调 logtraffic(ctx, c, LGTYP_ASCII)（3777、4473、4497 行——普通输出/回显路径）；「所有会话输出」模式在 4242 行以 LGTYP_DEBUG 喂更原始的数据流。logtraffic（logging.c:208-214）只在 logtype 与喂入的 mode 一致时才写，所以两种模式天然分流。
2. **SSH 层（ssh/bpp1.c、bpp2.c、bpp-bare.c）**：每个 SSH 包进出时调 log_packet。LGTYP_PACKETS 只记解密后的有意义包（带包类型名），LGTYP_SSHRAW 连带原始数据，原始数据前带时间戳（logging.c:302-308，方便定位延迟发生在哪端）。

### 4.7 SSH 包 hex 转储（log_packet，logging.c:262-380）

包体按经典 hexdump 排版：每行 16 字节，左边偏移量、中间十六进制、右边 ASCII（不可打印字符显示 `.`）。脱敏标记由 censor 层给出，两种处理：
- `PKTLOG_BLANK`：该字节打成 `XX`，右侧 ASCII 显示 `X`（内容占位保留长度）。
- `PKTLOG_OMIT`：整段省略，改打 `(N bytes omitted)`。
同时 SSH 层的 event log（连接过程消息，如主机密钥提示）在包日志模式下也写进文件（logevent_internal，logging.c:216-223），换行统一替换为空格。

### 4.8 SSH 脱敏（censor1.c / censor2.c）

界面那两个勾对应 PacketLogSettings 的 omit_passwords / omit_data，由每个 bpp 在 log_packet 前调用 ssh1/ssh2_censor_packet 生成 blanks 数组：
- **忽略会话数据**：SSH2 的 CHANNEL_DATA / CHANNEL_EXTENDED_DATA（SSH1 的 STDOUT/STDERR/STDIN/CHANNEL_DATA）里的数据字符串整段 OMIT——即日志里看不到你敲的命令和回显。
- **忽略已知的密码域**：仅当包由客户端发出（sender_is_client）。SSH2 解析 USERAUTH_REQUEST，认证方法为 "password" 时把密码字段 BLANK 成 XX；SSH1 对密码/TIS/CCARD 认证包**整包 BLANK**，X11 转发请求里的伪造认证数据也 BLANK。
- 两项默认值：omitpass=true（默认防泄密），omitdata=false（默认保留会话内容）。

### 4.9 会话中途改设置（log_reconfig，logging.c:405-427）

会话中重开配置面板改日志设置时：若文件名或日志类型变了 → 关旧文件、换新 Conf、重新走 logfopen（相当于开一个新日志文件）；只改其它选项（如脱敏勾选、flush）则无缝沿用当前文件。注意 logtype 在 log_init 时拷贝快照进 ctx->logtype，脱敏选项 PacketLogSettings 也是各 bpp 初始化时的快照，中途改动是否生效取决于各 bpp 的 reconfig 实现。

## 五、小结（一句话版）

面板本身只是把 8 个配置项写进 Conf；真正干活的是 logging.c 的一个四状态小状态机：终端/SSH 两路人马往里喂数据，它按类型过滤、按需打码（SSH 包模式再过一层 censor 脱敏）、按占位符算出文件名、按冲突策略开文件，然后落盘——写坏了就永久装死，免得刷屏报错。
