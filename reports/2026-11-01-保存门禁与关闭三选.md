# 保存按钮脏门禁与关闭三选提示

日期：2026-11-01
基线：main@`accaeef`
需求：主人——①保存按钮默认禁用，脏数据检查控制状态（与初始配置不一致启用、改回一致禁用，初始化与每次变更时重算）；②保存启用时，点保存弹改动清单确认；点窗口关闭弹附清单的三选提醒（直接退出 / 取消 / 保存并退出）。

## 一、方案：最大化复用 10-19 已有的未保存跟踪机制

排查发现 10-19「会话设置交互改造」已建立完整的 dirty 基础设施（windows/controls.c）：`dp->dirty` 标志、undo 快照栈（dlg_note_change 在每次 VALCHANGE 前 snapshot）、`dlg_has_unsaved_changes`、`dlg_update_apply_buttons`（按 ctrlbox->apply_button/undo_button 置灰）、WM_CLOSE 的 ask_save_changes 三键对话框（IDD_SAVECHANGES）——**只是启动框（do_config）从未开启 track_changes，这套设施一直没生效**。

本改造将其全面激活并升级：

| 改动 | 文件 | 说明 |
|---|---|---|
| 启动框开启跟踪 | windows/dialog.c do_config | track_changes=true、baseline=conf_copy(conf)、ctrlbox 挂接（初版漏了 ctrlbox，按钮门禁被守卫短路——实测抓出） |
| 保存按钮接门禁 | config.c | 非 midsession 分支 `b->apply_button = ssd->savebutton`，dlg_update_apply_buttons 自动置灰驱动 |
| 基线快照字段 | platform.h / controls.c | dlgparam 新增 baseline；dlg_mark_clean 重基（保存后清 undo 栈并刷新 baseline） |
| 实时比较 | utils/conf_data.c | 新增 `conf_equal()`：按 conf_key_info 逐字段比较（STR/STR_AMBI/INT/BOOL/FILENAME/FONT，CONF_protocol 特判）。**双向实时**——改回原值按钮复暗、关闭拦截同步解除 |
| 改动清单生成 | utils/conf_data.c | 新增 `conf_describe_changes()`：逐字段 diff，格式「关键字: 旧值 → 新值」，协议显示名称（SSH/串口/Telnet/Raw/裸 ssh 连接） |
| 保存确认弹窗 | config.c + dialog.c | 新 dlg API `dlg_confirm_save()`：保存前弹清单（message_box OKCANCEL），取消不保存 |
| 关闭三选升级 | windows/dialog.c + putty-common.rc2 | IDD_SAVECHANGES 扩为带清单区（IDC_CHANGE_LIST 多行只读框），按钮文案改「保存并退出 / 直接退出 / 取消」；WM_CLOSE 生成清单传入；「保存并退出」在启动框走 cn_persist_default_settings（与保存按钮同一保护链），在会话中框走 apply |
| 保存主体提取 | config.c | `cn_persist_default_settings()`：H3 串口保护 + 连接目标落盘为干净默认态（空主机/22/SSH）+ 内存还原；供保存按钮与「保存并退出」共用 |
| Unix stub | unix/dialog.c | dlg_confirm_save 返回 true（diff 函数为跨平台通用代码） |

## 二、过程中的关键排障

1. **按钮门禁不生效**：do_config 漏设 `dp->ctrlbox`，dlg_update_apply_buttons 的守卫短路——实测抓出并补上。
2. **比较结果滞后一步**：dlg_update_apply_buttons 原在 dlg_note_change（变更前）调用，实时比较拿到的是上一步状态（实测「改 2222 显示上一步的脏状态」）。修正：移至 dlg_send_event 的 handler 执行**之后**重算。
3. **STR_AMBI 断言崩溃**：conf_equal/describe 对 STR_AMBI 键误用 conf_get_str（上游断言 value_type==STR）。改用 conf_get_str_ambi。
4. **链接错误**：两函数最初放 settings.c，puttygen 不链接该库（undefined reference）——挪至 utils/conf_data.c（puttygen 链 utils）。
5. **取消后仍退出**：WM_CLOSE 分支 `return 0` 使对话框过程报告「未处理」，默认过程复活直接关窗——10-19 的潜伏 bug（当时为粘滞 dirty 语义，且从未被测试）。全部改 return TRUE。
6. **测试脚本三连坑**：VkKeyScan 在 win32api；tasklist GBK 解码；UIA 对模态弹窗 capture 校验不稳（invalid_target），改用 PrintWindow 自截 + pywin32 WM_COMMAND 触发按钮。
