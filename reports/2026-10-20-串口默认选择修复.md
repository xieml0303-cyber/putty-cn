# 串口下拉默认值修复：插上物理串口后不再停留在蓝牙 COM 口

日期：2026-10-20
涉及文件：`src/config.c`、`src/storage.h`、`src/windows/storage.c`、`src/unix/storage.c`

## 问题

用户反馈：机器上插着物理串口（一般为 COM3），打开配置窗口切到串口协议后，串行口下拉默认仍是 COM4，不会自动选中 COM3。

## 根因

`fill_serial_port_list()`（`src/config.c`）原来的逻辑只有一条回退规则：

- 保存的端口仍在本机串口列表里 → 原样保留；
- 保存的端口已不存在 → 回退到列表第一项。

Windows 的蓝牙虚拟串口（`\Device\BthModem*`，本机为 COM4–COM7）长期存在于 `HKLM\HARDWARE\DEVICEMAP\SERIALCOMM`，因此注册表里保存的 COM4 永远「存在」，插上 COM3 也不会触发回退，下拉就一直停在蓝牙口上。

## 修复

1. 新增平台接口 `serial_port_is_bluetooth(const char *port)`（`src/storage.h` 声明）：
   - Windows 实现遍历 `SERIALCOMM`，找到该端口对应的设备路径，含 `BthModem` 即判定为蓝牙虚拟口；
   - Unix 实现返回 `false`（Unix 不枚举串口）。
2. `fill_serial_port_list()` 增加一条分支：保存的端口存在但属于蓝牙虚拟口，且列表中有真实串口时，自动改选第一个真实口并同步写回 `CONF_serline`。
3. 顺带补上 `get_serial_ports()` 里 `valname` 的终止符保护（注册表枚举不保证补 `\0`）。

这样三条规则合起来是：

| 情况 | 结果 |
| --- | --- |
| 保存的是真实口且仍在 | 保持用户选择 |
| 保存的口不存在 | 选列表第一项（真实口优先） |
| 保存的是蓝牙口，且有真实口 | 自动切到第一个真实口 |
| 保存的是蓝牙口，机器上没有真实口 | 保持蓝牙口，不乱切 |

## 验证

本机当前只有蓝牙口 COM4–COM7（物理线未插），注册表 `SerialLine=COM4`，正好是故障现场。

1. **无真实口不误切**：新构建启动 → 会话页切「串口」→ 下拉显示 `COM4`，选中索引 0。通过。
2. **有真实口会切换**：临时把 `serial_port_is_bluetooth()` 改成「COM5 不算蓝牙」，编出测试版 `putty_probe.exe`，同样操作 → 下拉显示 `COM5`，选中索引 1。通过。验证后已恢复源码并重建正式版。
3. **正式版回归**：恢复后再次运行，仍为 `COM4`。通过。

验证脚本：`reports/probe_serial_default.py`（可传 exe 路径作参数）。

## 附：构建环境注意

本次构建首次失败，原因是 msys64 的 GCC 运行时依赖不在 PATH 中，`cc1.exe` 因找不到 `libmpfr-6.dll` 静默退出（无任何错误输出）。构建前需：

```bash
export PATH="/c/msys64/mingw64/bin:$PATH"
cd src/build && ninja putty
```
