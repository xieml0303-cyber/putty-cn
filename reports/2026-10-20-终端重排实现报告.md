## 一、目标与范围

窗口宽度变化时，终端不再沿用 PuTTY 原版"逐行截断/补空格"的处理方式，而是把整个缓冲区（屏幕 + 回滚历史）按逻辑行重新折行。范围按用户要求一次做全：

- 屏幕内容重排；
- 回滚历史（scrollback）一并重排；
- 光标位置、视口滚动位置随之重新映射；
- 窄化→宽化的往返不丢字符、不产生虚假换行标记。

## 二、改动位置

| 文件 | 改动 |

| `src/terminal/terminal.c` | 新增重排器（约 290 行）与 `term_size()` 集成；`power_on()` 底部锚定修正 |
| `src/test/test_terminal.c` | 新增 `test_reflow()`（约 164 行），覆盖 7 组场景 |

`term_size()` 中的入口条件：

```c
if (term->cols > 0 && term->rows > 0 && newcols != term->cols &&
    sblen + count234(term->screen) <= REFLOW_MAX_LINES)
    reflow_buffer(term, newrows, newcols, newsavelines);
else
    /* 原版逐行截断/补空格路径 */
```

只有"宽度变化"才触发重排；纯行数变化仍走原逻辑（行数变化不改变已有行的折行位置，重排无收益）。缓冲区总行数超过 `REFLOW_MAX_LINES`（20000）时降级回原行为，避免一次性解压全部历史造成内存尖峰。

## 三、算法流程

`reflow_buffer()` 的六个阶段：

1. **接管缓冲区**：把 scrollback 的压缩行逐条 `decompressline_and_free()`，与 screen 的行一起取出到数组 `src[]`，两个 234 树清空但保持有效。
2. **拼逻辑行**：从 `src[i]` 起，若其 `lattr` 带 `LATTR_WRAPPED` 则与后继行拼接，直至遇到不带该标记的行为止。拼接长度受 `REFLOW_MAX_LOGIC_LEN`（262144 字符）约束，超限则提前断开。`LATTR_MODE` 非 `LATTR_NORM` 的行（双宽/双高模式）不参与拼接，保持原样。
3. **拼平**：把逻辑行内容拷入一条临时 termline `flat`，使切分时可以向前看一个字符。
4. **按新宽度切分**：每行取 `min(剩余, newcols)` 个字符生成新行；若边界后一格是 `UCSWIDE`（宽字符右半格），说明真字符在前一格，于是回退一格，多出的那格标 `LATTR_WRAPPED2`（纯填充空格，后续重排不得并入正文）。宽度小于一个宽字符的极端情况保底取 1 格。
5. **光标与视口映射**：预先算出光标在逻辑行内的偏移，再用每行的 `row_off[]` 反查新行号与新列号；视口位置以"距缓冲区末尾的行数"保持不变量，滚动查看历史的用户不会被弹回底部。
6. **重建**：按 `top` 切分点把前半部分压缩后写回 scrollback（超出 `newsavelines` 的最旧行直接丢弃），后半部分写回 screen，不足 `newrows` 补空行。

## 四、关键难点与处理

**尾部填充行**：原文行长度不是新宽度整数倍时，切分会多出一行只有空格的尾行。该尾行若前面是 `LATTR_WRAPPED` 则删除，但绝不删除光标所在行，否则会破坏"光标在行尾等待输入"的状态。

**虚假换行**：DECAWM 关闭（不自动换行）时写入的超长行，原版 `termline` 里第一行并不带 `LATTR_WRAPPED`。重排切分时会如实补上该标记（因为新行确实是被宽度切断的），测试专门校验了这一点。

**底部锚定回归**：`power_on()` 原先用"屏幕总行数"作内容高度，屏幕自带的空行会把真实内容顶掉一行（3 行内容显示成 2 行）。改为用 `find_last_nonempty_line()+1` 定位真实内容底部后再锚定。

**视口不跳变**：`term_size()` 内部会 `swap_screen()`，而该函数触发 `seen_disp_event()`，在"显示活动时滚到底部"设置开启时会丢掉用户当前的滚动位置。重排路径全程保护 `disptop`（进入前保存、swap 后恢复、退出前再恢复一次）。

**历史截断顺序**：新的 `newsavelines` 若小于现有历史长度，必须在重排前先丢弃最旧的行。否则重排会把即将被淘汰的行重新拉回屏幕，导致"重置会话"等清空历史的操作失效。

## 五、验证

单元测试 `src/test/test_terminal.c::test_reflow()`，7 组场景全部通过：

1. 80 列 100 字符 → 40 列，校验 40+40+20 的切分位置、`LATTR_WRAPPED` 标记与光标 (2,20)。
2. 40 列 → 80 列合并回 2 行，光标 (1,20)，字符总数不变。
3. 宽度往返 80→37→80→21→80→100→80，每一步字符总数恒为 100，最终内容与标记正确。
4. 宽字符：21 个 U+AC00 在 21 列下不被劈成半个字，回到 40 列后右半格为 `UCSWIDE`、换行标记正确。
5. scrollback 重排：40 行 × 80 列（16 行已滚出屏幕）窄化到 40 列后，历史从 16 行变 56 行，首行内容与换行标记、光标 (23,39) 全部符合预期。
6. 滚动中的视口（`disptop = -5`）在再次 resize 后仍保持非零偏移。
7. 关闭自动换行的超长行不被误标为换行，重排后正确分段。

构建验证：`ninja -C build` 全量通过，产出 `putty.exe`、`puttytel.exe`、`test_terminal.exe` 等。`putty.exe` 可正常启动（以中文本地化的"命令行错误"提示框验证了 GUI 与字符串资源加载正常）。

## 六、已知限制

- **替代屏幕（alt screen）不重排**：`term_size()` 开头会切回主屏，重排只作用于主屏；alt 屏的行（vim、less 等全屏程序）仍按原逻辑压缩/补齐，返回 alt 屏时由程序自身重绘。这是刻意取舍：alt 屏内容属于程序所有，擅自重排会与程序的坐标假设冲突。
- **超长缓冲区降级**：总行数超过 20000 时退回原逐行处理，表现为窄化后长行被截断。如需放开，可提高 `REFLOW_MAX_LINES`，代价是重排期间 scrollback 全部解压的内存占用。
- **单逻辑行上限**：单个逻辑行超过 262144 字符时提前断开拼接，极端长行（如未换行的大文件 `cat`）会出现拼接边界不精确，但不丢字符。
