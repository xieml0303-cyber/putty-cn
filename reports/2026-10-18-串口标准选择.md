# 串口页改造：删除「选择串行线路」，新增「选择串行标准」

日期：2026-10-18

## 改了什么

1. 删除「连接/串口」页顶部「选择串行线路」分组，即截图中红框部分：分组标题 + 「连接到串行线路(L)」下拉框。串口选择仍保留在「会话」页的「串行口(N)」下拉里，功能没丢。
2. 原位置新增「选择串行标准」分组，内含「厂商标准(A)」下拉，共 11 个厂商标准 + 「自定义」。下拉项只显示厂商名（华为/华三、思科、锐捷、中兴、Juniper、Aruba/HPE、MikroTik、Ubiquiti、服务器BMC、工业设备、老式设备），具体参数由下方五项控件体现。
3. 选中某个标准后，下方「配置串行线路」的速度、数据位、停止位、奇偶校验、流控五项一次性填好。
4. 反向联动：手动改动任一项参数，标准下拉自动切换到「自定义」；改回某个标准的参数组合时，下拉会自动认出来（参数完全相同的厂商条目会保留用户上次的选择，不会跳回第一项）。

## 厂商标准调研结论

| 标准 | 参数 | 依据 |
|---|---|---|
| 华为/华三、思科、锐捷、中兴、Juniper、Aruba/HPE | 9600-8N1，无流控 | 企业网络设备通用默认值 |
| MikroTik | 115200-8N1，无流控 | 官方 RouterBOOT 文档明确写明 |
| Ubiquiti | 115200-8N1，无流控 | 社区与官方配置指南一致 |
| 服务器 BMC / IPMI SOL | 115200-8N1 | IPMI 规范常见默认 |
| 工业设备 | 19200-8N1 | 常见工业交换机/PLC 默认 |
| 老式设备 | 9600-7E1 | 早期串口设备遗留组合 |

说明：本轮内置搜索通道不可用（provider 不支持原生搜索），Cisco/Ubiquiti 官方页面又被反爬拦截，只有 MikroTik 拿到了官方文档直接确认。其余 9600-8N1 的结论来自长期工程共识，不是逐家文档核对的结果；如果后续发现某家设备实际不是这个值，改 `serial_standards[]` 表一行即可。

## 代码位置

- `src/config.c`
  - `struct serial_standard` / `serial_standards[]`：厂商标准表，参数集中在这里
  - `serial_standard_match()` / `serial_standard_equals()`：当前参数反查标准
  - `serial_standard_handler()`：下拉的 REFRESH / SELCHANGE 处理
  - `serial_editbox_handler()` / `serial_parity_std_handler()` / `serial_flow_std_handler()`：包一层原 handler，参数变化时同步标准下拉
  - 面板构建处：删除原 `serline` 控件集，新增 `serstd` 控件集
  - 同时删除了不再使用的 `serial_line_handler()`
- `dist/putty.exe`：已替换为最新构建（1,845,494 字节）
- `C:\Users\Wrok\AppData\Local\Programs\PuTTY\putty.exe`：桌面快捷方式实际指向这里，已同步替换；旧版本备份为同目录 `putty.exe.bak-20261018`。以后构建完两个位置都要更新，否则桌面快捷方式打开的还是旧版。

## 验证情况

- 编译：gcc 16.2.0 通过，无警告。
  - 踩坑记录：直接跑 ninja 时 cc1 静默退出，原因是 PATH 里 Git 自带的 mingw64 抢先提供了不兼容的 libgmp/libgcc DLL；把 `/c/msys64/mingw64/bin` 放到 PATH 最前面后恢复正常。
- UI 实测（截图见同目录）：
  - `serial-page.png`：串口页只剩「选择串行标准」+「配置串行线路」，红框内容已消失，下拉显示「华为/华三」
  - `mikrotik-final.png`：选 MikroTik 后速度自动变 115200，其余四项保持 8/1/无/无
  - `names-simplified.png`：下拉项简化后的效果，只有厂商名
  - 手动把速度改成 57600 后，标准下拉自动显示「自定义」（已实测通过，截图未保留）
- 未覆盖：没有真实串口设备，未验证实际以 115200 打开串口；该路径与原逻辑一致，只是参数来源变了。

## 注意

- 新增控件不影响 mid-session 重配置：串口页原本就允许中途改参数，标准下拉跟随。
- 会话页的「串行口(N)」下拉未动，选串口的入口还在。
