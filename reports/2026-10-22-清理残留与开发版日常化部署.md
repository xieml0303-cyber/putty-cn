## 二、开发版能否日常使用

结论：可以，且与正式版无性能差异。

依据：

- `src/build/CMakeCache.txt` 中 `CMAKE_BUILD_TYPE:STRING=Release`，Release 标志为 `-O3 -DNDEBUG`，即优化全开、断言关闭。这不是带调试断言的 Debug 构建。
- 编译器为 mingw64 gcc，生成器 Ninja，与安装包内程序同一次构建产物（安装包 Source 直接引用 `dist`）。
- 功能上包含本次全部改造：窗口固定左上角、尺寸偏差修正、关闭保存行列数、拖动实时重排。

### 为什么不直接用 `dist` 目录

`dist/` 是 Git 跟踪的仓库目录：

1. `git checkout` 或切换提交会让里面的 exe 变成对应历史版本的旧程序
2. 重新构建会直接覆盖同名文件
3. `git status` 会因二进制变化频繁变脏

因此复制到 `%LOCALAPPDATA%\Programs\PuTTY-cn` 独立运行。该路径与 Inno 安装包的默认安装位置一致，但本次未安装任何安装包，也没有生成卸载项——想彻底移除只需删掉这个文件夹。

### 已知局限

- **F1 帮助不可用**：`dist` 产物版本信息标注「未含内置帮助」，本机也无 `putty.chm`（原 Program Files 内那份随 MSI 卸载删除）。源码 `src/doc` 下有 `.but` 源文件，但构建中文 CHM 需要 halibut 工具链与翻译资源，本机均无，本次未处理。
- 若日后需要帮助文件，可从上游发布包取一份 `putty.chm` 放入部署目录，PuTTY 会按同目录查找。

## 三、后续更新方式

改代码并重新构建后，重复一次复制即可：

```bash
cp -f dist/putty.exe dist/puttygen.exe dist/plink.exe dist/pscp.exe \
      dist/psftp.exe dist/pageant.exe dist/puttytel.exe \
      "/c/Users/Wrok/AppData/Local/Programs/PuTTY-cn/"
```

配置仍存于注册表 `HKCU\Software\SimonTatham\PuTTY`，与程序所在路径无关，换目录不影响已有会话。

## 四、无待定事项

用户已明确不需要安装包版本，故不再安装 Inno 包；Release 资产仍保留供他人下载，两条路径互不影响。
