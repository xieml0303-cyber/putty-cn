# 桌面快捷方式改为实时联动构建产物（2026-10-22）

## 一、改动前的状态

不满足实时需求。此前快捷方式指向 `%LOCALAPPDATA%\Programs\PuTTY-cn\putty.exe`，那是一份从 `dist/` 复制出来的**副本**。每次改代码后必须手工再复制一次，快捷方式才有新版——正是用户不想要的「改完再去覆盖」模式。

## 二、改动后的机制

桌面与开始菜单两个 `.lnk` 的目标统一改为构建产物本体：

```
C:\Users\Wrok\Repos\putty-cn\src\build\putty.exe
```

`src/build/` 是 CMake + Ninja 的直接输出目录，被 `src/.gitignore` 第 72 行 `/build` 忽略，git 的任何操作（checkout、reset、清理）都不会动它。因此链路变成：

```
改源码 → ninja 构建 → src/build/putty.exe 被覆盖 → 桌面图标双击即最新
```

快捷方式本身此后**永远不需要再改**，也不需要任何复制步骤。

## 四、清理旧副本

`C:\Users\Wrok\AppData\Local\Programs\PuTTY-cn\` 已删除。理由：快捷方式不再指向它，留着会形成「两份程序、版本可能不一致」的隐患——实际上验证时它就已经落后于构建产物了。原件均保留在 `dist/` 与 `src/build/`，删除无信息损失。

## 五、需要知道的限制

1. **PuTTY 正在运行时无法构建**。Windows 会锁定正在执行的 exe，链接阶段会报 `cannot open output file putty.exe: Permission denied`。编译前先关掉运行中的窗口即可。
2. **`src/build` 被清理后快捷方式会短暂失效**。若执行 `cmake` 重新配置到新目录或删除整个 build 目录，需要先重新构建，路径本身不变时图标会自动恢复可用外观。
3. **`dist/putty.exe` 目前落后于 `src/build`**。本次验证重建产生的二进制与 `dist` 内那份仅存在 PE 时间戳差异，功能一致，故未回写、未提交，避免产生无意义的二进制变更记录。下次有实质改动时再同步 `dist` 并更新安装包。

实时联动已实现并实测通过，无需用户额外操作。
