## 测试中发现的坑（对使用者有实际影响）

1. **GUI 版 putty 不支持 `-batch`**。该选项是 plink 的，putty.exe 传入会弹「命令行错误：option "-batch" not available in this tool」。
2. **`putty host command` 写法有陷阱**。putty 的 tooltype 含 `TOOLTYPE_PORT_ARG`，而 `-P` 不会置位 `seen_port_argument`，于是 host 后的第一个参数被当成端口号：`putty 127.0.0.1 "echo hello"` 实际尝试连接端口 0，报「网络错误: 无法分配请求的地址」。远程命令应改用 `-m <命令文件>` 传入。plink 没有这个问题。
3. **该构建无法导入 OpenSSH/PEM 私钥**。`-i` 加载 OpenSSH 新格式或旧 PEM 格式均报「无法使用」，必须使用 PuTTY 原生 `.ppk` 格式。puttygen 0.85 命令行不支持 `-o` 导出，测试用的 PPK 由脚本按 v3 规范（HMAC-SHA256）生成。
4. 测试服务器端需监听 `client.on('error')`，否则客户端断开触发 ECONNRESET 会使 ssh2 服务器进程崩溃。

## 复现方式

测试脚本已入库到本仓库 `tests/`：
- `server-main.js` / `server-lib.js`：本地 SSH 测试服务器（密码 testuser/testpass，接受任意公钥）
- `test-putty.ps1`：四项测试驱动
- `gen-ppk.js`：生成 ed25519 PPK v3 私钥

运行：先 `node server-main.js`，再执行 `powershell -File test-putty.ps1`。

## 结论

中文版 PuTTY 的远程连接核心功能正常：密码与公钥两种认证、远程命令执行、中文回显、端口转发、交互终端均通过实测。界面汉化未影响协议层行为。
