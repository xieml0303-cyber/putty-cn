## 需求

连接类型选「串口」时，串行口输入框改为下拉框，下拉内容为本机真实存在的串行口。

## 实现

### 1. 串口枚举（新接口）

`storage.h` 新增：

```c
char **get_serial_ports(int *count);
void free_serial_ports(char **ports, int count);
```

- `windows/storage.c`：读注册表 `HKLM\HARDWARE\DEVICEMAP\SERIALCOMM`，该键由串口驱动维护，值名是设备路径、数据是 `COMx`。枚举后按端口编号插入排序（保证 COM2 排在 COM10 前面），最多 64 个。
- `unix/storage.c`：返回空列表（Unix 下用户直接输入设备路径）。

### 2. 会话页「串行口(N)」

该控件与「主机名称(或 IP 地址)(N)」共用同一个控件，切协议时只换标签和内容。改动：

- `config.c` 创建处：`ctrl_editbox` → `ctrl_combobox`（可编辑下拉框，既能选也能手输）。
- 新增 `fill_serial_port_list()`：清空列表 → 填入真实串口 → 回填当前值。清空前先 `dupstr` 保存当前值，避免清空触发的事件把 `Conf` 里的值改掉后指针失效。
- `config_host_handler` 的 `EVENT_REFRESH`：协议为串口时填充列表；其它协议清空列表，保持原有「主机名」输入行为。

### 3. 「连接/串口」面板的「连接到串行线路(L)」

为保持一致同步改成下拉框，新增 `serial_line_handler`（`EVENT_REFRESH` 填充列表、`EVENT_VALCHANGE` 写 `CONF_serline`），替换原来的 `conf_editbox_handler`。

### 关键点：为什么换控件是安全的

PuTTY 的 `ctrl_combobox()` 在数据结构上就是 `CTRL_EDITBOX` 加 `editbox.has_list = true`，Windows 前端据此创建 `COMBOBOX`（`CBS_DROPDOWN`）而不是 `EDIT`。因此：

- `dlg_editbox_set/get`、`dlg_label_change` 全部照常工作；
- `dlg_listbox_clear/add` 内部按控件类型自动发 `CB_` 系列消息，本来就支持组合框；
- `COMBOHEIGHT == EDITHEIGHT == 12`，面板布局尺寸完全不变；
- `winctrl_handle_command` 对 `has_list` 的控件专门处理 `CBN_SELCHANGE`：读出选中项文本写回编辑区，再触发 `EVENT_VALCHANGE`，所以真实点选一定会写进 `Conf`。

## 验证

本机 `SERIALCOMM` 实际内容：COM3（VCP0，USB 转串口）、COM4–COM7（蓝牙 Modem）。

1. 切到「串口」，输入框变为带箭头的下拉框，当前值仍为 COM1 —— 见 `serial-2.png` 之前的会话页截图。
2. 展开下拉：`CB_GETCOUNT = 5`，条目依次 COM3、COM4、COM5、COM6、COM7，与本机真实串口完全一致，排序正确。截图 `serial-2.png`。
3. 选中第一项后编辑区显示 COM3 —— 截图 `serial-7.png`。
4. 端到端：选中 COM3 → 点「打开(O)」，成功打开串口会话窗口，标题 `COM3 - PuTTY`（VCP0 设备存在且可打开）—— 截图 `serial-10.png`。作为对照，未选中任何项时点「打开」报错为 `Opening '\\.\COM1': Error 2`，说明配置值确实随下拉选择变化。

注：用 `CB_SETCURSEL` 模拟选中不会触发 `CBN_SELCHANGE`，必须补发 `WM_COMMAND` 通知才会写配置；这是测试手段的细节，真实鼠标点选不受影响。
