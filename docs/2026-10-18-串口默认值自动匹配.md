# PuTTY 中文版：串口默认值改为自动匹配本机真实端口

日期：2026-10-18
仓库：`C:\Users\Wrok\Repos\putty-cn`
产物：`src/build/putty.exe`（1,840,589 字节，SHA256 前缀 `06da75a3`）

## 一、问题

配置窗口「串行口(N)」默认显示 `COM1`，但本机并不存在 COM1，直接点「打开」会报
`Opening '\\.\COM1': Error 2`。本机实际串口（`HKLM\HARDWARE\DEVICEMAP\SERIALCOMM`）：

| 设备路径 | 端口 | 性质 |
|---|---|---|
| `\Device\VCP0` | COM3 | FTDI USB 转串口（真实 console 口） |
| `\Device\BthModem1` | COM4 | 蓝牙虚拟串口 |
| `\Device\BthModem2` | COM5 | 蓝牙虚拟串口 |
| `\Device\BthModem3` | COM6 | 蓝牙虚拟串口 |
| `\Device\BthModem0` | COM7 | 蓝牙虚拟串口 |

## 二、根因

`COM1` 来自三个层次，只改一处无效：

1. 源码 `conf.h`：`serline` 的 `DEFAULT_STR("COM1")` 是中文版改造时写死的默认值。
2. 注册表：`HKCU\Software\SimonTatham\PuTTY\Sessions\默认设置\SerialLine = COM1`
   （键名 URL 编码为 `%E9%BB%98%E8%AE%A4%E8%AE%BE%E7%BD%AE`），启动时优先生效。
3. 界面填充：`fill_serial_port_list()` 只把真实串口填进下拉列表，再把配置里的当前值原样
   回填编辑框，从不校验该值是否存在，所以下拉框里明明没有 COM1，编辑框仍显示 COM1。

## 三、改动（3 个文件）

### 1. `src/conf.h`

```c
CONF_OPTION(serline,
    VALUE_TYPE(STR),
    DEFAULT_STR(""),
    SAVE_KEYWORD("SerialLine"),
)
```

默认值由 `"COM1"` 改为空串，含义变为「未指定，由界面按本机实际情况选择」。这也与
`src/test/test_conf.c` 中原有的 `test_str_simple(CONF_serline, "SerialLine", "")` 断言恢复一致。

### 2. `src/config.c`

`fill_serial_port_list()` 增加 `Conf *conf` 参数与存在性校验：

- 填充列表时顺带判断当前值是否在真实串口列表中；
- 若为空或不存在，取列表第一项写回 `CONF_serline`，并显示到编辑框；
- 两处调用点（`serial_line_handler`、`config_host_handler`）同步传入 `conf`。

`conf_set_str()` 只修改数据、不触发界面通知，因此在 `EVENT_REFRESH` 内写回不会造成递归刷新。

### 3. `src/windows/storage.c`

`get_serial_ports()` 枚举时记录每个端口是否为蓝牙虚拟口（值名含 `BthModem`），排序规则改为
「真实端口在前、蓝牙端口在后，同类按端口号升序」，保证自动回退取到的第一项是可用的物理串口。

## 六、行为说明

- 换机器或换 USB 口导致 COM 号变化时，配置界面会自动落到当前存在的第一个真实串口，
  不再停留在不存在的端口上；手动输入的值只要真实存在则保持不变。
- 本机当前唯一真实串口为 COM3；拔掉 USB 转串口线后，程序会回退到列表中的下一项（蓝牙口），
  这是「本机确实只有这些串口」的预期行为。
