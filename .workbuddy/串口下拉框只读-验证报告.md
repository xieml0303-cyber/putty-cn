# 串口号下拉框只读改造 — 验证报告

## 问题现象

改完代码、构建通过后，主人打开 PuTTY 仍能手动输入串口号。原因不是代码没生效，而是**部署没跟上**：

| 文件 | 修改前时间 | 说明 |
|---|---|---|
| src/build/putty.exe | 13:17 | 新构建，含只读改造 |
| C:\Users\Wrok\AppData\Local\Programs\PuTTY\putty.exe | 12:09 | 旧版本，主人实际运行的就是它 |
| dist/putty.exe | 12:09 | 旧版本 |

已把 13:17 的新构建覆盖到安装目录和 dist，两处现均为 1,841,358 字节。

## 改动内容

1. `src/dialog.h`：新增 `dlg_editbox_set_readonly()` 声明。
2. `src/windows/controls.c`：实现只读开关，对组合框内部的 Edit 子窗口置 `ES_READONLY`，下拉列表选择不受影响；文字颜色保持正常（未用灰色）。
3. `src/unix/dialog.c`：GTK 对应实现（`gtk_editable_set_editable`），保持一致。
4. `src/test/fuzzterm.c`：补空桩，保证测试目标可编译。
5. `src/config.c`：
   - `serial_line_handler`（会话页串口框）与 `config_host_handler`（串口模式下同一控件）在串口协议时调用只读，SSH/Telnet 时清除只读。
   - `config_protocols_handler` 在协议切换时刷新，保证切回串口重新只读。
